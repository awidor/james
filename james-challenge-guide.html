The story

Monday morning at SPIEberdyne

SPIEberdyne Systems runs a data platform called Deep Thought. Every department gets its reports there. When something breaks, people write in the Teams channel #deep-thought-support. James reads along. He can answer, ask a question, open or update a ticket in the ITSM tool, or call a human from the support team. Company, people and tickets are made up.

Known incident, open since Mon 06:40

INC-4711 Nightly run Order Intake failed (P2)

Affected: Order Intake report. The report shows Friday's data. The data team is working on it and expects a fix around 10:00.

What James knows

Actions, priorities, knowledge

Actions

  • answerJames replies in the channel.
  • askJames asks a follow-up question.
  • ticketJames creates a new ticket in the ITSM tool.
  • update_ticketJames adds information to an existing ticket.
  • handoverJames pulls in a human from the support team.
  • ignoreJames does nothing.

Priorities

P1The platform or a business-critical report is down for many users.
P2A report is wrong or outdated for a whole department.
P3One person is affected, or a workaround exists.
P4Question, wish or idea.

Service hours: Mon to Fri, 07:00 to 18:00. Outside these hours nobody from the support team reads the channel.

Knowledge base

  • KB-01
    Access

    Access to reports only via a service request. Only the report's data owner may approve it. For HR reports the data owner is the HR department.

  • KB-02
    Login

    Deep Thought uses the company login. Users reset their password themselves in the self-service portal. Support never asks for passwords.

  • KB-03
    Data freshness

    The nightly run starts at 02:00. By 06:00 yesterday's data is available. Each report shows its data date in the bottom left corner.

Output format

actions.json is a list with one object per message. Set ticket to null if James does not open or update a ticket.

{
  "message_id": 1,
  "action": "answer | ask | ticket | update_ticket | handover | ignore",
  "reply": "what James posts in the channel, two sentences max, otherwise null",
  "ticket": {
    "type": "incident | service_request",
    "priority": "P1 | P2 | P3 | P4",
    "title": "short title",
    "description": "what happened, who is affected",
    "requester": "name from the message",
    "links": [
      "INC-4711"
    ]
  },
  "reason": "one sentence on why James acts this way"
}
Rules

Before you start

  • James runs offline on your laptop. No cloud APIs, no API keys, no accounts.
  • Windows, macOS or Linux. Starting James takes one or two commands.
  • You may use a language model if it runs locally, for example with Ollama. Your code checks the model's answer before James posts it or opens a ticket.
  • The frontend runs on localhost or as a local file. No hosting.
  • AI tools are allowed while you build. Tell us in the README how you used them.
  • Stop after about 3 hours. Unfinished is OK. Write down what is missing.
